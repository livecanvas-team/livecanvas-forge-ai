Connect Codex in four steps

Start in WordPress: open LiveCanvas > AI Bridge > Connections. You do not need an Application Password or a global MCP configuration.

1:1
One project = one WordPress site.

Open only the Codex, OpenCode, Claude, or Cursor project that belongs to the site you are connecting.

Codex setup

Use the setup prompt generated by WordPress. Do not create a global MCP entry.

0 of 4 complete
    Ready. The coding agent is connected to the correct WordPress site.
    When should I use Local runtime?

    Use Local runtime (advanced) only when the agent must read local theme files, run Sass or WindPress builds, discover local assets, or run visual checks. For normal page, partial, template, media, and design-system work, keep Direct Mode.

    The coding agent cannot see AI Bridge
    • Confirm that you opened the same project where the generated configuration was saved.
    • Trust the project when Codex asks. Untrusted projects ignore their .codex/config.toml file.
    • Close the coding agent completely, then reopen it. The first npm start can take up to 60 seconds.
    • Disable any older livecanvas-forge MCP entry so only the site-specific server remains enabled.
    The site URL or fingerprint is wrong

    Stop without writing. Revoke the old session in WordPress, remove that site's stale MCP block from this coding-agent project, and generate a new setup from the correct site.

    Reads work but writes do not

    First make the smoke test pass. Then enable the required write abilities in AI Bridge. If the session does not include the write scope, revoke it and connect again.

    Before any write, verify that the site URL and fingerprint reported by the coding agent match the Connections screen.
    LiveCanvas AI Bridge 0.2 is staging beta software. Use preview, audit IDs, and rollback for write workflows.
