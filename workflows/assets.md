# Manage assets and compile styles

Read the verified pipeline and existing asset sources before changing them. Use WordPress media tools for site images; preserve attachment identity, alt text and responsive image behavior when appropriate. Do not assume an agent's personal files or unrelated project assets belong to this site.

For Picowind, inspect the installed WindPress runtime/manifest and source entries. Compile through the available WindPress tool, passing current site context and source_revision when storing. Support the installed manifest paths, including assets/dist. Do not hardcode windpress/build. A failed build must preserve the last valid compiled cache. DaisyUI or Typography being installed is insufficient; check current compiled evidence before generating dependent classes.

For Picostrap, read its compile manifest, use the existing Sass variables and Bootstrap components, then compile with the Picostrap tool. Do not introduce Tailwind utilities or disable unrelated plugins to avoid a compiler error. For theme-native/Barebone, inspect the existing enqueue and build process and report an unavailable compiler instead of claiming compilation.

Refresh context after changing any source. Reject a compiled bundle based on an older source revision. Verify successful storage and the asset loaded by the page separately. Report compilation failure and whether the previous valid cache is still present; do not label the whole change complete while required styles are missing.

Child-theme source writes use the authenticated WordPress file coordinator even from a local MCP client. A verified private snapshot is required before the write. Keep its changeset.id for conflict-aware Undo; do not bypass a failed coordinator with shell writes. Source-file Undo does not restore a compiled cache or its build metadata. A file write can affect the live site before any publication step.

Picostrap bundle storage requires fresh site write_context, acknowledge_shared and the current compile manifest source_fingerprint. Write Sass sources separately before reading this context and compiling. Keep the returned bundle changeset.id: Undo with fresh site context restores its CSS and compilation metadata, rejects intervening edits and preserves unrelated theme settings. Files and database metadata are not crash-atomic. An interrupted journal or needs_recovery status requires inspection. The server reports externally supplied compilation as client_reported; the MCP compiler can report its own successful Dart Sass execution. Neither is a visual check. Coordinated source-plus-bundle Undo remains unavailable.

WindPress compiled CSS, its source map and compilation evidence also return a private changeset.id. Undo uses fresh site context and shared acknowledgement. It rejects changed cache bytes, permissions or evidence. A build without a source map removes the obsolete map, which can be restored by Undo. Failed storage must report whether artifact compensation was verified. The remote store-windpress-cache Ability uses the same coordinator but needs explicit enablement in the administrator's remote write allowlist. The separate theme.json output, source-volume edits and media are outside this cache changeset. Recheck current source compatibility and browser/CDN caches after restoration.
