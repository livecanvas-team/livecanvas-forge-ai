# Build a single or archive template

Start with the public target URL and get_write_context. Inspect the effective template and its evidence, including LiveCanvas assignments, theme fallback and Twig/Latte/PHP sources. A WordPress article's post_content is often only the editorial body. For example, when the resolver reports picowind-child/views/single.twig, edit that verified child-theme template for article layout; leave the article body unchanged.

If rendering is unresolved or differs for authenticated users, say so and obtain a representative permitted rendering check. Do not select a template solely from its filename or from an optional caller flag. Read the active parent template before creating a child override. Never write to the parent theme through an alternative tool after a rejection.

For a LiveCanvas Dynamic Template, inspect assignment rules and the existing markup. Preserve existing query and content bindings; confirm whether the request concerns single, archive, taxonomy or another target. Use the granular template action with the exact ID. For a child-theme fallback, obtain a separate theme_file context for the verified relative path and use the theme-file tools.

Explain the shared impact and retain the site's document shell. Acknowledge shared scope only with the user's authorization. Test an affected URL and an unaffected control URL where possible. Check article content and comment settings remain unchanged when the request was only about layout.
